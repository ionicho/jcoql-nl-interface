=== ESEMPIO: Filtro su Valore Calcolato ===
NL: "Elementi con prezzo scontato inferiore a una soglia"
SBAGLIATO: FILTER CASE WHERE .prezzo * (1 - .sconto / 100) < 30
GIUSTO: FILTER CASE WHERE .categoria = 'esempio' AND .sconto > 20
SPIEGAZIONE: Non usare calcoli in linea nel FILTER. Filtra su campi reali dello schema
(vedi la sezione "SCHEMA MONGODB REALE" per i nomi di campo effettivi del database
corrente), non su risultati calcolati al volo.

=== ESEMPIO: Filtro Semplice con KEEP OTHERS ===
NL: "Elementi con un valore superiore a una soglia"
QUERY: GET COLLECTION collezione; FILTER CASE WHERE .campo > 15 KEEP OTHERS;
NOTA: Usa sempre i nomi di campo reali indicati nello schema del database corrente,
non inventarli.

=== ESEMPIO: Raggruppamento - SINTASSI CORRETTA ===
NL: "Raggruppa per una categoria"
SBAGLIATO: GROUP PARTITION true BY .campo INTO gruppo
GIUSTO: GROUP PARTITION TRUE BY .campo INTO .gruppo
SPIEGAZIONE: TRUE deve essere maiuscolo. Il nome dopo INTO deve SEMPRE iniziare con
un punto (.) - è un campo del documento risultante, non un identificatore libero.
QUERY: GET COLLECTION collezione; GROUP PARTITION TRUE BY .campo INTO .gruppo;

=== ESEMPIO: Raggruppamento su Campo Annidato ===
NL: "Raggruppa per un sotto-campo (es. città dentro un indirizzo)"
QUERY: GET COLLECTION collezione; GROUP PARTITION TRUE BY .indirizzo.citta INTO .gruppi_per_citta;
NOTA: I campi annidati si scrivono come sequenza di segmenti puntati
(.campoEsterno.campoInterno), esattamente come appaiono nello schema del database.

=== ESEMPIO: Negazione su Valore ===
NL: "Elementi diversi da un certo valore"
QUERY: GET COLLECTION collezione; FILTER CASE WHERE .campo != 'valore' KEEP OTHERS;

=== ESEMPIO: Negazione su Booleano ===
NL: "Elementi senza una certa caratteristica"
QUERY: GET COLLECTION collezione; FILTER CASE WHERE .campo_booleano = false KEEP OTHERS;

=== ESEMPIO: Valori Numerici con Simboli di Valuta ===
NL: "Elementi con prezzo superiore a un importo in euro/dollari/sterline"
QUERY: GET COLLECTION collezione; FILTER CASE WHERE .prezzo > 1000 KEEP OTHERS;
NOTA: Ignora i simboli di valuta (£, $, €) nella richiesta dell'utente. Estrai solo
il valore numerico.

=== ESEMPIO: Verifica Presenza Campo ===
NL: "Elementi dove un certo campo è presente/valorizzato (non nullo)"
QUERY: GET COLLECTION collezione; FILTER CASE WHERE FIELD .campo ISNOTNULL KEEP OTHERS;
NOTA: Molti campi opzionali possono avere valore null per una parte dei documenti -
usa questo pattern quando l'utente chiede esplicitamente "presente"/"registrato"/
"assegnato" su un campo.

=== ESEMPIO: JOIN - Sintassi Corretta ===
NL: "Unisci due collezioni in base a un campo in comune"
QUERY: JOIN OF COLLECTIONS collezione1 AS a, collezione2 AS b CASE WHERE .a.campo = .b.campo;
SPIEGAZIONE: La condizione di uguaglianza va SEMPRE in CASE WHERE, MAI in ON (riservato
a ON GEOMETRY per casi spaziali). Non aggiungere MAI "KEEP OTHERS" a un JOIN a meno che
l'utente non lo chieda esplicitamente: trasformerebbe il collegamento filtrato in un
prodotto cartesiano completo. Verifica sempre, dallo schema del database corrente, quale
campo di una collezione corrisponde realmente a quale campo dell'altra prima di scegliere
la condizione - non assumere che campi con lo stesso nome siano automaticamente collegati.

=== ESEMPIO: GET DICTIONARY + TRANSLATE - Sintassi Corretta ===
NL: "Traduci un campo usando il dizionario delle categorie"
SBAGLIATO: GET DICTIONARY delle@nomedb AS dict; GET COLLECTION collezione; FILTER GENERATE ADD FIELDS { .campo_tradotto: TRANSLATE(.campo, dict) };
GIUSTO: GET DICTIONARY categorie_dizionario@nomedb AS dict; GET COLLECTION collezione; FILTER GENERATE ADD FIELDS { .campo_tradotto: TRANSLATE(.campo, dict) };
SPIEGAZIONE: Nell'esempio SBAGLIATO il nome scelto per la collezione dizionario ("delle")
è una parola presa dalla frase della richiesta ("usando il dizionario DELLE categorie"),
non il nome di una collezione reale - errore comune e sempre sbagliato. Il nome dopo
GET DICTIONARY deve essere SEMPRE il nome di una collezione che esiste davvero nello
SCHEMA MONGODB REALE del database corrente (mostrato sopra in questo prompt), mai una
parola presa alla lettera dalla frase in linguaggio naturale. Se non è chiaro dalla
richiesta quale collezione reale dello schema sia il dizionario voluto, non scrivere
affatto GET DICTIONARY (e nemmeno TRANSLATE) invece di indovinare un nome sbagliato.
